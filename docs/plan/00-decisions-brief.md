# 00 — ملخص القرارات (مصدر الحقيقة الموحّد)

كل القرارات الثابتة التي تلتزم بها بقية وثائق الخطة: الأسماء، الأرقام، المراحل، الحزمة التقنية. مكتوبة بإنجليزية تقنية كمرجع مباشر للمطوّرين.

Every writer/reviewer agent MUST follow this brief. Where this brief decides something, the document must agree with it verbatim (names, numbers, phases). Where the brief is silent, decide sensibly and mark the decision under a "قرارات مفتوحة" (open decisions) section at the end of the doc.

## 0. Writing rules
- Language: Arabic (Modern Standard, clear, professional) with English technical terms kept in English (e.g. monorepo, oRPC, Prisma, Routine, Takeover, WebSocket). Code, file paths, package names, commands, env vars: English.
- Format: GitHub-flavored Markdown. Use tables for comparisons/lists of options, Mermaid (```mermaid) for architecture/sequence/ER diagrams, fenced code for code/commands/schemas.
- Every doc starts with `# NN — <Arabic title>` matching the file name number. Second line: one-sentence purpose.
- Cross-link sibling docs with relative links, e.g. `[09 — كمبيوتر البوت](./09-computer-runtime.md)`.
- Use status markers exactly: 🟢 MVP (Phase 1) · 🟡 v1 (Phases 2–4) · 🔵 v2 (after launch) · 🧱 Scaffold. No other emojis.
- Target length: 150–400 lines per doc. Dense and concrete, no filler, no marketing fluff. Prefer concrete numbers, names, limits, defaults.
- End each doc (where relevant) with `## قرارات مفتوحة` listing undecided points with a recommended default.
- Do NOT include any AI model identity of the author, no "generated by" lines in the docs.
- Numbers: use Western digits (0-9). Dates: ISO or Arabic months.

## 2. References (facts gathered 2026-10-04)
### Grok Bot (xAI + Cursor; beta since Aug 2026) — product reference
- A Bot = AI teammate with name, title (short job), description/instructions; persistent conversation per bot; Primary bot starred.
- One persistent managed Linux cloud computer per user shared by all their bots (files, browser sessions, logins shared); each bot has its own screen; bots are not separate security boundaries. Work under `/workspace` persists; elsewhere may be lost on recovery.
- Routines: schedule (timezone) or event trigger; notify policy ("when silence is the right result"); up to 50 routines/bot; keeps last 20 runs; editing schedule/instructions/testing requires desktop.
- Skills: walk the bot through a path once, save as skill, rerun on schedule.
- Connectors ("plugins", mentioned with @): Google Docs/Sheets/Slides/Gmail, Notion, X, Finance, Stripe Link; multiple accounts per service; secure credential fields masked and kept from the model. Preference order: structured plugin → official API/CLI → cloud browser → local computer access.
- Group chats, bots message each other, delegation/handoff, voice memos, drafts you approve before send, approvals pause work.
- Desktop: macOS (arm64/x64), Windows (x64/arm64), Linux. Mobile: iPhone/iPad iOS 18+, Android 9+. Mobile = quick handoff interface: message/dictate, attach files/screenshots, watch the shared computer, take over (password/2FA/CAPTCHA) then return control; push notifications for result/question/approval. Share sheet on iOS; Android accepts text.
- Limits: max 50 bots+group chats per user; no model selection; weekly usage allowance; "Route egress through this desktop" setting (Sept 22 2026); local computer access asks every time.
### Rakazo (open source, Apache-2.0, github.com/elie222/rakazo) — architecture reference
- Monorepo: `apps/` (web, api, worker, desktop Electron, mobile Expo, public site), `packages/` (domain, contracts, persistence, adapters, UI, test utils), `infra/` (local services, computer images), `docs/` (architecture, ops, release).
- Stack: TypeScript, React 19 + Vite, Tailwind, Electron, Expo, Hono + oRPC, PostgreSQL + Prisma, Better Auth, Graphile Worker.
- Sandbox providers: Docker/Compose, E2B, Daytona, CreateOS, Box, trusted local. Team computers (shared) + Private computers.
- Integrations: Composio, Pipedream Connect, MCP remote tools, OpenAPI tools, encrypted on-server credentials. Voice: ElevenLabs/OpenAI/Cartesia/Fish Audio. BYO model (OpenRouter etc.).
- Deploy: Docker Compose with published images; installer script generates .env; Caddy for HTTPS; Electron can run everything locally via published images; Expo app is an API client. Requires Node 22.22+, pnpm 9, Docker.
### xAI Grok API pricing (Oct 2026, verify before launch)
- Grok 4.5: $2.00/M input, $6.00/M output, 500K context. Grok 4.3: $1.25/M input ($0.20/M cached), $2.50/M output, 1M context. Grok 4.20 variants cheaper. Beyond 200K context tokens, rates double. grok-4/grok-3 legacy.

## 9. Core limits & defaults (use consistently)
- Max 50 bots + group chats per organization (raise on request). 50 routines/bot, keep last 20 RoutineRuns. Run defaults: maxSteps 40, 30 min per message run, 2 h per routine run; approval wait timeout 24 h. Screenshot retention 30 days; access logs 90 days; hard delete 30 days after account deletion. Memory dedup threshold cosine 0.92. Realtime replay window 5 min via Outbox. Rate limiting per user/org.
- Tool risk classes: safe / sensitive / destructive; destructive and external-send actions require Approval by default.
- Realtime event names: message.created, run.status, run.delta, run.step, approval.requested, approval.decided, computer.status, computer.takeover, routine.run.finished, notification, presence.
- Run statuses: queued, running, paused_for_approval, paused_for_takeover, completed, failed, cancelled. Computer statuses: stopped, starting, running, idle, error.
