# 18 — الفريق وأسلوب العمل

الغرض: الأدوار وسير العمل اليومي ومعايير الإنجاز.

## الفريق المقترح

| الدور | العدد | المسؤولية |
|---|---|---|
| Tech lead / Backend | 1 | API وdomain وdb وauth والمعمارية |
| Backend / AI | 1 | agent وsandbox وconnectors وevals |
| Frontend | 1 | web وdesktop وui |
| Mobile | 1 | mobile وui-native |
| DevOps | 0.5 | infra وCI وrelease |
| مصمم | 0.5 | الهوية ونظام التصميم وتجربة RTL |
| PM / QA | 1 | الأولويات والاختبار اليدوي والمتاجر |

## سير العمل

- **الفروع:** `main` محمي، وفروع قصيرة العمر باسم `feat/` و`fix/` و`chore/`، وPR صغير مع squash merge.
- **الالتزامات:** Conventional Commits (`feat(api): ...`).
- **المراجعة:** مراجع واحد على الأقل، وCODEOWNERS لكل مجال، وقالب PR يتطلب فحص RTL.
- **الإصدارات:** Changesets، ووسوم `desktop-v*` و`mobile-v*` للتطبيقات.
- **القرارات:** أي تغيير معماري يُسجَّل كـ ADR في `docs/adr`.
- **اللغة:** الكود والتعليقات والـ commits بالإنجليزية، والوثائق بالعربية.

## تعريف الإنجاز (Definition of Done)

1. اختبارات وحدة وتكامل تغطي التغيير، والتفويض مختبَر.
2. `pnpm lint && pnpm typecheck && pnpm test` ناجحة.
3. الواجهة مراجَعة بـ `ar` (RTL) و`en` وبالوضعين الفاتح والداكن.
4. التوثيق وADR محدَّثان عند الحاجة، وchangeset مضاف إن لزم.
5. لا أسرار في الكود، ولا تراجع في الأداء أو التغطية.

## الإيقاع

- سبرنتات أسبوعان، وتجربة داخلية (dogfooding) أسبوعياً بالبوتات نفسها.
- مراجعة المخاطر والتكلفة (tokens وساعات الكمبيوتر) نهاية كل مرحلة.

## قرارات مفتوحة

- أداة التتبع: **التوصية** GitHub Projects مع Issues لتبقى بجانب الكود.
